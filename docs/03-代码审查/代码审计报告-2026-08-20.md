@Component
public class TokenCounter {
    public static final int MESSAGE_FORMAT_OVERHEAD = 4;
    
    private final Encoding encoding;
    private final Cache<String, Integer> cache;

    public TokenCounter() {
        EncodingRegistry registry = Encodings.newDefaultEncodingRegistry();
        this.encoding = registry.getEncoding(EncodingType.CL100K_BASE);
        this.cache = Caffeine.newBuilder()
                .maximumSize(10_000)
                .expireAfterWrite(Duration.ofMinutes(10))
                .build();
    }

    public int count(String text) {
        if (text == null || text.isEmpty()) return 0;
        return cache.get(text, encoding::countTokens);
    }

    public int countChatMessages(String systemText, String userText) {
        return count(systemText) + MESSAGE_FORMAT_OVERHEAD
                + count(userText) + MESSAGE_FORMAT_OVERHEAD;
    }
}

### 2.3 EvidenceVerificationService.java ✅ 完美实现三级匹配

**实现亮点**：
```java
@Service
public class EvidenceVerificationService {
    private static final double FUZZY_THRESHOLD = 0.8;
    private static final double SEMANTIC_THRESHOLD = 0.85;

    boolean matchesEvidence(String evidenceContent, String candidateText) {
        String normalizedEvidence = normalize(evidenceContent);
        String normalizedCandidate = normalize(candidateText);

        if (normalizedEvidence.isEmpty() || normalizedCandidate.isEmpty()) return false;

        // Level 1: Exact containment (fast path, ~90% hit rate)
        if (normalizedCandidate.contains(normalizedEvidence)) return true;

        // Level 2: Fuzzy match (handles minor wording differences)
        if (fuzzyMatch(normalizedEvidence, normalizedCandidate, FUZZY_THRESHOLD)) return true;

        // Level 3: Semantic match (handles synonyms, paraphrase)
        return semanticMatch(evidenceContent, candidateText, SEMANTIC_THRESHOLD);
    }

    private boolean fuzzyMatch(String s1, String s2, double threshold) {
        int len1 = s1.length();
        int len2 = s2.length();
        int maxLen = Math.max(len1, len2);
        if (maxLen == 0) return true;
        if (maxLen > 500) return false; // skip expensive comparison for very long text
        if ((double) Math.abs(len1 - len2) / maxLen > (1 - threshold)) return false;

        int distance = levenshteinDistance(s1, s2);
        double similarity = 1.0 - (double) distance / maxLen;
        return similarity >= threshold;
    }

    private int levenshteinDistance(String s1, String s2) {
        // Optimize memory: use 1D array, swap so shorter string is the column
        int len1 = s1.length();
        int len2 = s2.length();
        if (len1 < len2) return levenshteinDistance(s2, s1);

        int[] prev = new int[len2 + 1];
        int[] curr = new int[len2 + 1];

        for (int j = 0; j <= len2; j++) prev[j] = j;

        for (int i = 1; i <= len1; i++) {
            curr[0] = i;
            for (int j = 1; j <= len2; j++) {
                int cost = (s1.charAt(i - 1) == s2.charAt(j - 1)) ? 0 : 1;
                curr[j] = Math.min(Math.min(curr[j - 1] + 1, prev[j] + 1), prev[j - 1] + cost);
            }
            int[] tmp = prev;
            prev = curr;
            curr = tmp;
        }
        return prev[len2];
    }
}
```

**审计结论**：
- ✅ 正确实现了三级匹配策略
- ✅ Levenshtein 距离算法优化（1D 数组，内存友好）
- ✅ 正确处理了长文本边界（maxLen > 500 跳过）
- ✅ 长度差异预检查，避免无效计算
- ✅ 语义匹配失败时优雅降级（catch Exception, return false）

    record BudgetConfig(int maxRounds, long durationMs, long maxTokens) {}

    public AgentState run(Long mediaId, VideoContext context, ModeProfile profile) {
        validateContext(context);
        BudgetConfig budget = calculateDynamicBudget(context);
        try (AgentExecutionBudget.Scope ignored = AgentExecutionBudget.open(budget.durationMs())) {
            return runWithinBudget(mediaId, context, profile, budget);
        }
        // ...
    }

    private BudgetConfig calculateDynamicBudget(VideoContext context) {
        long totalDurationMs = context.segments().stream()
                .mapToLong(s -> s.endMs() - s.startMs())
                .sum();
        int segmentCount = context.segments().size();

        int dynamicRounds;
        long dynamicDurationMs;
        long dynamicTokens;

        if (totalDurationMs < 300_000L && segmentCount < 10) {
            // Simple: short video with few segments
            dynamicRounds = 1;
            dynamicDurationMs = 30_000L;
            dynamicTokens = 20_000L;
        } else if (totalDurationMs < 1_800_000L) {
            // Medium: up to 30 minutes
            dynamicRounds = 2;
            dynamicDurationMs = 60_000L;
            dynamicTokens = 40_000L;
        } else {
            // Complex: longer than 30 minutes — use full config budget
            dynamicRounds = maxRounds;
            dynamicDurationMs = maxDurationMs;
            dynamicTokens = maxEstimatedTokens;
        }

        // Never exceed configured ceiling
        return new BudgetConfig(
                Math.min(dynamicRounds, maxRounds),
                Math.min(dynamicDurationMs, maxDurationMs),
                Math.min(dynamicTokens, maxEstimatedTokens));
    }

    private enum ResumeDecision {
        RETURN_IMMEDIATELY,
        REPAIR_AND_CONTINUE,
        CRITIC_CHECKPOINT,
        CONTINUE_FROM_ROUNDS
    }
}

### 2.5 DeepSeekUtils.java ✅ 完美实现熔断器+重试器

**实现亮点**：
```java
@Component
public class DeepSeekUtils {
    private final CircuitBreaker circuitBreaker;
    private final Retry retry;

    public DeepSeekUtils(...) {
        // ...
        
        // Circuit breaker: sliding window of 10 calls, opens at ≥50% failure rate,
        // waits 60s in open state, then allows 3 half-open probes before deciding.
        CircuitBreakerConfig cbConfig = CircuitBreakerConfig.custom()
                .slidingWindowSize(10)
                .failureRateThreshold(50)
                .waitDurationInOpenState(java.time.Duration.ofSeconds(60))
                .permittedNumberOfCallsInHalfOpenState(3)
                .slidingWindowType(CircuitBreakerConfig.SlidingWindowType.COUNT_BASED)
                .build();
        this.circuitBreaker = CircuitBreaker.of("llm-deepseek", cbConfig);
        this.circuitBreaker.getEventPublisher()
                .onStateTransition(event -> log.warn("llm_circuit_breaker_transition from={} to={}",
                        event.getStateTransition().getFromState(),
                        event.getStateTransition().getToState()));

        // Retry: exponential backoff 500ms → 10s, max 3 attempts, retry on retriable errors.
        RetryConfig retryConfig = RetryConfig.<String>custom()
                .maxAttempts(3)
                .waitDuration(java.time.Duration.ofMillis(500))
                .intervalBiFunction((attempt, resultOrException) -> {
                    if (resultOrException.isLeft()) {
                        return Math.min(500L * (1L << (attempt - 1)), 10_000L);
                    }
                    return 0L;
                })
                .retryOnException(e -> isRetriableModelFailure(e))
                .build();
        this.retry = Retry.of("llm-deepseek", retryConfig);
        this.retry.getEventPublisher()
                .onRetry(event -> log.info("llm_retry_attempt lastException={}",
                        event.getLastThrowable() != null
                                ? event.getLastThrowable().getMessage() : "null"));
    }

    private String chat(String stage, String prompt) {
        long started = System.nanoTime();
        try {
            // Circuit breaker wraps retry: opens after sustained failures, rejects calls when open.
            // Retry wraps invokeModel: up to 3 attempts with exponential backoff for retriable errors.
            String response = circuitBreaker.executeSupplier(() -> {
                try {
                    return retry.executeCallable(() -> {
                        String r = invokeModel(prompt);
                        if (r == null || r.isBlank()) {
                            throw new RetriableException("模型返回空响应");
                        }
                        return r;
                    });
                } catch (MaxRetriesExceededException e) {
                    throw new IllegalStateException("模型调用达到最大重试次数", e);
                } catch (RuntimeException e) {
                    throw e;
                } catch (Exception e) {
                    throw new IllegalStateException("模型调用失败", e);
                }
            });
            telemetry.modelCall(stage, SYSTEM_POLICY + "\n" + prompt, response,
                    inputPricePerMillion, outputPricePerMillion, started);
            return response;
        } catch (CallNotPermittedException e) {
            telemetry.failCurrentStage(stage, started);
            throw new IllegalStateException("LLM 服务熔断中，请稍后重试", e);
        } catch (RuntimeException e) {
            telemetry.incrementCurrent("modelCallFailures", 1);
            telemetry.failCurrentStage(stage, started);
            if (!isRetriableModelFailure(e)) {
                throw new IllegalArgumentException("模型请求不可重试", e);
            }
            throw e;
        }
    }
}
```

**审计结论**：
- ✅ 正确引入了 Resilience4j CircuitBreaker 和 Retry
- ✅ 熔断器配置合理（滑动窗口 10，失败率 50%，60s 半开，3 次探测）
- ✅ 重试器配置合理（3 次尝试，指数退避 500ms→10s）
- ✅ chat() 方法正确组合了 circuitBreaker 和 retry
- ✅ 正确处理了 CallNotPermittedException（熔断器打开）
- ✅ 添加了事件监听器，记录状态转换和重试

### 2.6 AiService.java ✅ 已重构，但可进一步简化

**实现亮点**：
```java
@Service
public class AiService {
    private VideoContext resolveContext(MediaFile mediaFile, String userGoal,
                                        String traceId, AnalysisMode mode) {
        // Phase 1: Checkpoint or content-reuse (fast path, no lock needed)
        VideoContext fastPath = checkpointOrReuseFirst(mediaFile, userGoal, traceId);
        if (fastPath != null) return fastPath;

        // Phase 2: Acquire content lock and build with double-check
        String contentHash = AnalysisTaskKeys.normalizeContentHash(
                mediaFile.getId(), mediaService.contentHash(mediaFile.getId()));
        RLock contextLock = redissonClient.getLock(AnalysisTaskKeys.contextLock(contentHash));
        boolean locked = false;
        try {
            locked = contextLock.tryLock(CONTEXT_LOCK_WAIT_SECONDS, TimeUnit.SECONDS);
            return buildAfterLock(mediaFile, userGoal, traceId, contentHash, mode, locked);
        } catch (InterruptedException e) {
            Thread.currentThread().interrupt();
            throw new IllegalStateException("等待视频上下文构建锁被中断", e);
        } finally {
            if (locked && contextLock.isHeldByCurrentThread()) contextLock.unlock();
        }
    }

    private VideoContext checkpointOrReuseFirst(MediaFile mediaFile, String userGoal, String traceId) {
        VideoContext checkpoint = checkpointService.loadContext(mediaFile.getId());
        if (checkpoint != null) {
            telemetry.increment(traceId, "contextCheckpointHits", 1);
            return withGoal(checkpoint, userGoal);
        }
        String contentHash = AnalysisTaskKeys.normalizeContentHash(
                mediaFile.getId(), mediaService.contentHash(mediaFile.getId()));
        VideoContext reused = reuseContentContext(mediaFile, userGoal, traceId, contentHash);
        if (reused != null) return reused;
        return null;
    }

    private VideoContext withGoal(VideoContext ctx, String userGoal) {
        return new VideoContext(ctx.source(), userGoal, ctx.segments());
    }
}
```

**审计结论**：
- ✅ 拆分为 checkpointOrReuseFirst() 和 buildAfterLock()
- ✅ 添加了 withGoal() 辅助方法
- ✅ 逻辑更清晰，注释更明确
- ✅ 保持了原有的双重检查锁机制

**潜在问题**：

⚠️ **问题3：重构不够彻底**

虽然已经拆分了方法，但 `resolveContext()` 仍然有 20 行代码，包含了锁的获取和释放逻辑。

#### 问题模式 2：Docker 网络配置陷阱（迭代 3）

**现象**：
```
RemotingTooMuchRequestException: sendDefaultImpl call timeout
```

**根因**：
RocketMQ Broker 未配置 `brokerIP1`，注册了 Docker 内部 IP（172.18.0.7），客户端从宿主机无法访问。

**反思**：
> **"Docker 网络的坑：容器内部 IP vs 宿主机 IP"**

这是 Docker 部署消息队列的经典问题。Broker 向 NameServer 注册时，如果不指定 `brokerIP1`，会使用容器内部 IP。Producer/Consumer 从 NameServer 获取到这个 IP 后，从宿主机无法连接。

**关键教训**：
```yaml
# RocketMQ in Docker 必须配置 brokerIP1
rmqbroker:
  command: >
    sh -c "echo 'brokerIP1=127.0.0.1' >> broker.conf &&
           exec sh mqbroker -c broker.conf"
```

**改进建议**：
- 在 `docker-compose.yml` 中添加注释，说明 `brokerIP1` 的重要性
- 提供 `docker-compose.prod.yml` 用于生产环境
- 在启动时检查 RocketMQ 连通性

#### 问题模式 3：配置分散且不一致（迭代 4、6）

**现象**：
- Redis 连接失败（端口 6379 vs 6380，密码不匹配）
- 动态预算仍为 240s（环境变量未生效）

**根因**：
1. `application.properties`、`.env`、`docker-compose.yml` 三处配置不一致
2. `mvnw spring-boot:run` 不会自动加载 `.env` 文件
3. 配置的默认值与实际值不匹配

**反思**：
> **"配置的单源原则：一个值只能在一个地方定义。"**

我们在三个地方定义了 Redis 端口：
- `application.properties`: `spring.data.redis.port=${REDIS_PORT:6379}`
- `.env`: `REDIS_PORT=6380`
- `docker-compose.yml`: `ports: - "127.0.0.1:6380:6379"`

但 `application.properties` 的默认值是 6379，`.env` 不会自动加载，导致配置不生效。

**关键教训**：
```properties
# ❌ 错误：默认值与实际值不一致
spring.data.redis.port=${REDIS_PORT:6379}  # 默认 6379

# ✅ 正确：默认值就是实际值
spring.data.redis.port=${REDIS_PORT:6380}  # 默认 6380
```

**改进建议**：
1. 使用 `spring-dotenv` 库自动加载 `.env`
2. 或者在启动脚本中显式加载：`source .env && ./mvnw spring-boot:run`
3. 配置验证：启动时检查关键配置，fail-fast

#### 问题模式 4：硬编码的"假配置"（迭代 5）

**现象**：
```

```

**根因**：
`calculateDynamicBudget()` 中硬编码了 120s 上限：
```java
} else if (totalDurationMs < 1_800_000L) {
    dynamicDurationMs = 120_000L;  // ❌ 硬编码

    Math.min(dynamicDurationMs, maxDurationMs));  // 永远不会超过 maxDurationMs
```

**反思**：
> **"如果用户修改了配置却不生效，那这个配置就是假的。"**

我们在 `application.properties` 设置了 `agent.budget.max-duration-ms=300000`，但代码里硬编码了 120s，导致配置无效。

**关键教训**：
```java
// ❌ 错误：硬编码上限
dynamicDurationMs = 120_000L;

// ✅ 正确：基于配置计算
dynamicDurationMs = (long) (maxDurationMs * 0.8);
```

**改进建议**：
- 代码审查时检查所有"配置项"是否真正影响运行时行为
