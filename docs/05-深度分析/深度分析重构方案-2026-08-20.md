# 深度分析系统重构方案

> **最后更新**：2026-08-20

## 📋 问题诊断

### 当前系统的核心问题

通过实际测试发现，当前 Agent 输出的问题是：

**做的是"信息提取"，不是"知识分析"**

```
❌ 当前输出：
- 核心结论（5条）：视频说了什么
- 视频证据（12条）：时间戳 + 原话
- 建议（3条）：泛泛而谈

✅ 期望输出：
- 核心洞察：这意味着什么
- 推理过程：为什么重要
- 批判性分析：局限性和替代观点
- 可操作收获：如何应用
```

### 根本原因

1. **Prompt 设计太浅**
   - 只告诉 LLM "生成结论 + 证据"
   - 没有引导它进行深度思考
   - 输出格式限制了结构化推理

2. **Critic 只检查证据，不检查质量**
   - 只验证"证据是否支持结论"
   - 不检查"结论是否有深度"
   - 不检查"分析是否有洞察"

3. **输出格式太简单**
   - 只有 `conclusions` + `evidence` + `suggestions`
   - 无法表达推理过程
   - 无法表达批判性思考

## 💡 解决方案

### 1. 新的输出格式：`DeepAnalysisResult`

```java
public record DeepAnalysisResult(
    String executiveSummary,              // 一句话核心洞察
    String context,                       // 背景与重要性
    List<KeyInsight> keyInsights,         // 核心洞察（带推理）
    CriticalAnalysis criticalAnalysis,    // 批判性评价
    List<ActionableTakeaway> actionableTakeaways,  // 可操作收获
    List<Evidence> supportingEvidence,    // 支撑证据
    List<Section> sections                // 模式化段落
)
```

#### KeyInsight（核心洞察）
```java
public record KeyInsight(
    String insight,           // 洞察本身（不只是事实）
    String reasoning,         // 为什么这是重要的
    List<Evidence> evidence,  // 支撑证据
    String implications,      // 这意味着什么（影响/启示）
    List<String> relatedConcepts  // 相关概念/知识关联
)
```

**示例**：
```json
{
  "insight": "Reflection 范式通过在循环中引入独立的 Critic 节点，解决了 ReAct 范式缺乏结果自检的核心缺陷",
  "reasoning": "传统 ReAct 范式中，模型只能完成任务，但无法验证任务完成的质量。这导致错误会在循环中累积，最终产出不可靠的结果。",
  "evidence": [
    {"timestampMs": 60000, "source": "ASR", "content": "在 react 里模型只能完成，但是它并不看完成的", "claim": "ReAct 缺乏自检"}
  ],
  "implications": "这意味着在设计 Agent 系统时，必须考虑引入验证机制，否则系统的可靠性无法保证。",
  "relatedConcepts": ["Agent 可靠性", "自我修正系统", "质量控制"]
}
```

#### CriticalAnalysis（批判性分析）
```java
public record CriticalAnalysis(
    List<String> strengths,              // 论证的优点
    List<String> limitations,            // 局限性和假设
    List<String> alternativePerspectives // 替代观点
)
```

**示例**：
```json
{
  "strengths": [
    "通过对比 ReAct 和 Reflection 范式，清晰地展示了改进点",
    "使用 LangGraph 代码示例，让抽象概念具体化"
  ],
  "limitations": [
    "没有讨论 Reflection 节点的性能开销",
    "假设 Critic 模型的判断总是正确的，未考虑误判情况"
  ],
  "alternativePerspectives": [
    "可以使用更轻量级的验证方法（如规则检查）替代完整的 Critic 模型",
    "在某些场景下，ReAct 的简单性可能比 Reflection 的可靠性更重要"
  ]
}
```

#### ActionableTakeaway（可操作收获）
```java
public record ActionableTakeaway(
    String takeaway,        // 收获本身
    String application,     // 如何应用
    List<String> nextSteps, // 下一步做什么
    List<Evidence> evidence // 支撑证据
)
```

**示例**：
```json
{
  "takeaway": "在设计 Agent 系统时，应该引入独立的验证节点",
  "application": "在你的 Agent 工作流中，添加一个 Critic 步骤，在每个任务完成后进行质量检查",

    "实现 Critic 节点，并定义通过/失败的条件"
  ],
  "evidence": [...]
}
```

### 2. 新的 Executor Prompt

**关键改进**：引导 LLM 进行深度思考，而非简单总结

```
你是 Video Agent 的深度分析执行器。你的任务不是简单总结视频内容，而是进行深度分析和洞察提炼。

## 分析要求

1. **核心洞察**：不要只说"视频说了什么"，要回答"这意味着什么"
   - 识别视频的核心论点和隐含假设
   - 解释为什么这些观点重要
   - 关联到更广泛的知识背景

2. **推理过程**：每个洞察都要有推理支撑
   - 为什么这是重要的？（reasoning）
   - 这与其他概念有什么关系？（relatedConcepts）
   - 这意味着什么？（implications）

3. **批判性思考**：不只是接受视频观点
   - 论证的优点是什么？（strengths）
   - 有哪些局限性或假设？（limitations）
   - 有什么替代观点？（alternativePerspectives）

4. **可操作性**：不只是理论分析
   - 如何应用这些洞察？（application）
   - 下一步做什么？（nextSteps）
```

```java
    }
}
```
